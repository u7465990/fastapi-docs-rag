## 2. 真实索引：DashScope embedding 的 batch 限制

### 假设

第一次真实建索引会暴露 provider 的具体限制；此前只测过单条 embedding，没有测 batch。

### 第一次命令

```powershell
uv run --no-sync python scripts/ingest.py --limit 3
```

### 结果

```text
EmbeddingError: embedding request failed with HTTP 400:
Value error, batch size is invalid, it should not be larger than 10.: input.contents
```

### 分析

- 代码默认 `EMBEDDING_BATCH_SIZE=32`
- DashScope `text-embedding-v4` 单批最多 10 条
- 这是 provider 限制，不是解析或 Qdrant 问题

### 修复

在 `make_embedder` 里对 DashScope 做保护：

```python
batch_size = settings.embedding_batch_size
if "dashscope.aliyuncs.com" in settings.embedding_base_url and batch_size > 10:
    batch_size = 10
```

同时把默认值调到 10，并补测试。

### 验证

```powershell
uv run --no-sync python scripts/ingest.py --limit 3
```

结果：

```text
documents: 3
chunks: 20 (children 15)
build_collection: fastapi_docs_build_20261114T062139Z
alias: fastapi_docs_current
vectors: 15
index complete
```

再跑全量：

```powershell
uv run --no-sync python scripts/ingest.py
```

结果：

```text
documents: 155
chunks: 1661 (children 1363)
docs_version: 0.162.0
build_collection: fastapi_docs_build_20261114T062154Z
alias: fastapi_docs_current
vectors: 1363
index complete
```

### 原理

- 每个 child chunk 调一次 embedding，向量写入 Qdrant 的 named vector `dense`
- payload 同时带 `parent_text`、URL、section、`docs_version`、`is_deprecated` 等
- 写入临时 collection，成功后切 alias，避免半成品被查询
- `source_ref` 当前是 `unknown`，因为 C 工作区的 `data/raw/fastapi` 是文件快照、没有 `.git`

## 4. Chat API 和模型选择

### 实现

- `generation/llm.py`：OpenAI 兼容 chat client
- `generation/chat.py`：system prompt、上下文拼接、`[n]` 引用、拒答
- `POST /api/v1/chat`：检索 top-k -> 生成 -> 后端把编号映射成 sources

### 设计原则

- 模型只输出 `[n]`，不生成 URL
- 上下文不足时直接说没有足够信息
- 检索内容当作数据，不执行其中指令
- 命中废弃 API 时提示 `is_deprecated`

### 模型验证

```powershell
uv run --no-sync python scripts/check_providers.py
```

结果：

```text
embedding=text-embedding-v4 chat=qwen-turbo missing=[]
[embedding] OK model=text-embedding-v4 dim=1024
[chat] FAILED: HTTP 429 limit_requests
```

### 假设

`qwen-turbo` 的 429 是速率/额度限制，不是 Key 错；Key 错应该是 401，模型未开通通常是 403/404。

### 验证

```powershell
uv run --no-sync python scripts/check_providers.py --chat-only
```

换模型测试：

```powershell
$env:LLM_MODEL='qwen-plus'
uv run --no-sync python scripts/check_providers.py --chat-only
```

结果：

```text
[chat] OK model=qwen-plus reply='OK'
```

再测：

```text
[chat] OK model=qwen-flash reply='OK'
```

### 结论

- 最终用 `qwen-flash`，便宜且可用
- `qwen-turbo` 的 429 没有继续纠缠
- 真实 chat 返回 200，回答内容包含 `on_event` 废弃说明、`lifespan` 迁移代码和 `[2]` 引用

### 顺手修复：废弃 section 的子标题继承

真实 chat 的 source [2] 是：

```text
Lifespan Events > Alternative Events (deprecated) > startup and shutdown together
```

但它一开始 `is_deprecated=false`，因为 parser 只检查当前标题，没有继承父级 deprecated 标记。

修复：

- 当前标题 deprecated
- 或 path 中 H2/H3 祖先 deprecated
- 或 admonition 明确说明废弃

然后重建索引，source [2]、[3] 都正确标成 deprecated。

## 7. LLM 额度锁：从“平台限制”改成“应用硬限制”

### 背景

用户使用新账号免费额度；阿里云/百炼没有“把模型费用硬上限设为 0.01 元”的可配置硬停。平台侧只有余额、预算提醒、模型限流。

因此必须在应用层做硬限制。

### 设计

新增：

```dotenv
LLM_MAX_TOKENS_CAP=512
LLM_DAILY_REQUEST_LIMIT=50
LLM_DAILY_TOKEN_BUDGET=300000
```

流程：

```text
生成 messages
  -> 估算 token（字符数/3 + max_output，保守）
  -> Redis Lua 原子预占 request + tokens
  -> 超限 429，不调用 LLM
  -> 未超限才调用
```

### 为什么用 Redis Lua

- 并发请求不能先读再写，否则会超卖
- Lua 在 Redis 内原子执行：检查 request/token 上限、INCR、EXPIRE 一次完成
- Redis 不可用时返回 503，**不绕过额度**

### 验证 1：直接测 Redis DB15

```powershell
uv run --no-sync python -c "...DailyQuota(... request_limit=1, token_budget=1000)..."
```

结果：

```text
QuotaState(requests=1, tokens=10)
```

说明 Lua 正常。

### 验证 2：真实 chat 后看 Redis

```text
quota:llm:requests:20261114 = 1
quota:llm:tokens:20261114   = 4300
```

说明一次 chat 预占约 4300 token。

### 验证 3：强制超额

把 token key 设为 300000 后再请求：

```text
HTTP 429
{"detail":"daily LLM quota exhausted (requests 1/50, tokens 300000/300000)"}
```

然后清空测试 key，恢复当天额度。

### 边界

- 只锁 LLM chat，不锁 `/search` 的 query embedding
- 预占而不是按真实 usage 回补；LLM 失败也会消耗预占
- 这是“宁可少花钱，也不超支”的取舍

## 13. 今天的核心思考

1. **先证明链路，再优化质量。** 5/5 smoke 不是质量评估，但能避免在错误的层上 debug。
2. **平台限制要在应用层兜底。** 免费额度、欠费、429 都不可控；Redis 额度锁是唯一能“花到上限就停”的地方。
3. **Docker 网络问题优先用镜像/tag 解决，不要改代码。** Compose 卡住时先看镜像和 registry。
4. **前端不要暴露 dev server。** 生产必须 build + Nginx/Caddy；dev 5173 只在本机。
5. **同源 `/api` 比 CORS 更稳。** Web 由 Nginx 反代，Web 端不需要跨域；CORS 留给 Capacitor/移动端。
6. **多端不要先换框架。** React/Vue 都不是多端的关键；Capacitor/Tauri 才是壳。换 Vue3 只是重写成本。
7. **当前是“本地可演示”，不是“生产上线”。** 还缺 HTTPS、鉴权、评估、source_ref、备份和最终镜像验证。
